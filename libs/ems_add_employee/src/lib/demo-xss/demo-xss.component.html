Bagaimana Angular Melindungi Anda dari XSS?

Secara default, Angular menganggap semua nilai sebagai tidak tepercaya. Ketika nilai dimasukkan ke dalam DOM melalui interpolasi (seperti {{ '{{ payload }}' }}) atau properti binding, Angular secara otomatis melakukan context-aware sanitization atau escaping.

Halaman demo ini membandingkan binding default Angular yang aman dengan praktik berbahaya yang mem-bypass sistem keamanan Angular.

Input Payload XSS
Payload Preset untuk Dicoba:
@for (preset of presets; track preset.name) { }
1. Interpolasi Standard (Aman)
AMAN (Escaped)

Menggunakan {{ '{{ payload }}' }}. Angular mengonversi karakter HTML seperti < menjadi entitas teks aman.

{{ payload() }}
Hasil: Teks ditampilkan secara literal sebagai teks biasa. Script tidak akan dieksekusi sama sekali.
2. Properti Binding [innerHTML] (Aman)
AMAN (Sanitized)

Menggunakan <div [innerHTML]="payload">. Angular mengizinkan tag HTML dasar (seperti <b>, <a href>) tetapi menghapus kode javascript (seperti onerror, <script>).

Hasil: HTML dasar dirender dengan aman. Tag <script> atau atribut onerror secara otomatis dihilangkan dari DOM.
3. DomSanitizer Bypass (BAHAYA!)
RENTAN XSS

Menggunakan DomSanitizer.bypassSecurityTrustHtml(payload). Ini memaksa Angular untuk mempercayai payload HTML secara mentah.

PERINGATAN: Mengabaikan sanitasi berarti jika payload berisi script jahat (misalnya onerror gambar), script tersebut AKAN langsung dieksekusi di browser pengguna! Gunakan hanya jika sumber data 100% tepercaya dan telah divalidasi ketat di sisi server.
4. Manipulasi DOM Langsung lewat ElementRef (BAHAYA!)
RENTAN XSS

Menggunakan elementRef.nativeElement.innerHTML = payload. Ini mem-bypass seluruh ekosistem keamanan Angular dan langsung menulis ke browser.

PERINGATAN: Praktik manipulasi DOM langsung sangat tidak disarankan di Angular. Hal ini membuat aplikasi rentan terhadap serangan DOM-based XSS secara langsung karena tidak melewati proses sanitasi template Angular.
5. Custom Escape / Text-Only Rendering (Aman)
AMAN (Custom Cleaned)

Menggunakan sanitasi kustom untuk menggantikan karakter khusus HTML secara manual sebelum ditampilkan sebagai HTML biasa.

Hasil: Mengamankan output dengan mengubah kode tag HTML menjadi entitas teks biasa di tingkat variabel, menjamin keamanan mutlak meskipun dibinding menggunakan properti [innerHTML].
